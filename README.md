# VideoView v0.8.0

轻量级 Windows 桌面视频播放器，纯 Win32 自绘界面 + libmpv 播放核心。

## 功能

- 打开本地视频文件（拖放 / 文件对话框 / 命令行参数）
- 播放 / 暂停 / 停止
- 进度条拖动跳转，显示当前时间与总时长
- 音量控制 / 静音（音量与窗口尺寸跨启动保存）
- 画面自适应窗口：缩放窗口时视频区跟随重排，按原始宽高比缩放
- 影院模式（隐藏控制栏）与 `F11` 全屏
- **解码诊断面板**（`I`）：硬解是否生效、是否零拷贝、丢帧、实际帧率，
  外加一条能照着改的结论。诊断报告 `Ctrl+C` 一键复制
- **画面右键菜单**：打开、播放/暂停、停止、音轨 ▸、字幕轨 ▸、截图、
  逐帧前后、变速、跳转（开头 / ±10 秒 / 结尾）、影院模式、全屏、
  解码诊断、快捷键总览、复制诊断报告。系统原生菜单，菜单项按当前状态打勾、
  按可用性置灰
- **音轨 / 字幕轨**（`T`，或右键菜单 ▸）：菜单里按音频、字幕分组列出，
  `●` 标正在用的、`▸` 标文件默认轨。`J` / `L` 切上一条 / 下一条字幕轨，
  `A` 下一条音轨
- **播放列表**（`P`，或右键菜单 ▸）：多选几个文件拖进窗口就有列表了，
  `↑` `↓` 移动、`↵` 播放，鼠标点哪行播哪行。`●` 标正在放的那一条，
  `▸` 标这一条有随它一起拖进来的外挂字幕。`N` / `B` 切下一个 / 上一个，
  一个播完自动接下一个。到最后一条不循环（要循环得显式开 mpv 的
  `--loop-playlist`），只有一个文件时按 `N` 什么都不发生
- **同名字幕自动挂载**：把 `movie.mp4` 和 `movie.zh.srt` 一起拖进来，
  字幕会自动挂到那一条上（`movie.zh` / `movie.en` / `movie` 都算「同名字幕」，
  `movie2.srt` 不算）
- **高级模式**（画面右键菜单最上面那个勾）：关掉之后，0.3.0 起的那些
  高级项在菜单里全部**置灰**，`I` / `T` / `P` / `N` / `B` / `Ctrl+C`
  也不再响应。想用一个干净的基础界面就关掉它。
  **默认是开的** —— 第一次启动就把功能藏起来的话，用户只会以为功能坏了
- **外挂字幕**：把 `.srt` / `.ass` / `.ssa` / `.vtt` 拖进窗口即加载并当场选中，
  **不替换当前视频**
- **记住每个文件播到哪儿**：下次打开同一个文件自动跳回去，控制栏里文件名
  那一块显示 4 秒「已从上次的位置继续 12:34」。
  - 片头 2 秒内不记（跳过去等于没跳，还要白跑一次 seek）
  - **看到片尾就把那条删掉** —— 看到片尾意味着看完了，下次从头放
  - 记下来的位置超出文件长度（文件被换短了）时不跳，否则 mpv 会跳到片尾，
    用户看到的是「一打开就播完了」
  - 右键菜单里的「**从头播放**」是逃生口：自动续播是**没有界面提示**的
    动作，想重看一遍某个片段的人需要一条能明确表达「这个从头看」的路径
  - **不会清理「文件已经不在」的记录**。只靠 500 条上限控制大小 ——
    `is_file()` 分不出「文件没了」和「现在看不到」（U 盘没插、NAS 关机、
    网络盘断开），拿它当删除依据会把暂时看不到的进度永久删掉。代价是删掉
    的视频会一直占着名额，直到被上限挤出去
- **倍速、字幕大小、字幕编码会被记住**（和音量、窗口大小放在一起）。
  倍速在控制栏上有一个 `1.25x` 这样的标签，**只在不是 1.0 倍时出现** ——
  1.0 倍时多一行字对大多数人只是噪音
- **A-B 循环**：`Shift+←` 标记 A 点、`Shift+→` 标记 B 点、`Shift+L` 清除
  （或右键菜单 ▸ 时间）。设 A 点会清掉已设的 B 点；没标 A 点时「标记 B 点」
  是灰的 —— mpv 要两个点都有效才循环，只设一个等于没设
- **字幕延迟** `Ctrl+←` / `Ctrl+→`、`音频延迟** `Alt+←` / `Alt+→`，
  每次 ±0.05 秒（或右键菜单 ▸ 时间）。
  - 延迟是**看不见**的，所以菜单里「归零」那一项的标题带出当前值
    （`字幕延迟归零（+0.15）`），为 0 时置灰；每次用快捷键改动，控制栏
    文件名那一块显示 4 秒提示
  - **不跨重启保留**，但**跨文件保留**（一次会话里遇到一批同样编码问题的
    文件时，逐个重调很烦）
  - 没有「视频延迟」：它对应 mpv 的 `video-delay`，实测这份 libmpv 0.41
    里**没有**这个属性，所以只做了字幕与音频两个方向
- **字幕编码与字幕大小**（右键菜单 ▸ 字幕 ▸ 字幕编码 / 字幕大小）：
  编码给的是自动 / GBK / GB18030 / Big5 / Shift-JIS / EUC-KR / Latin-1，
  大小给的是 50%–200% 六档。编码**只对文本字幕文件生效** —— 内嵌字幕
  （包括 MKV 里的）由解封装器转成 UTF-8，这个设置管不了，所以外挂字幕
  显示成乱码时才需要它
- 截图（`S`），存到图片目录
- 快捷键：`空格` 播放/暂停、`Ctrl+O` 打开、`←` / `→` 快退快进、
  `↑` / `↓` 音量、`,` / `.` 逐帧、`[` / `]` 变速、`0`–`9` 百分比跳转、
  `Home` / `End` 开头结尾、`M` 静音、`T` 轨道菜单、`J` / `L` 字幕轨、
  `A` 切轨，`P` 播放列表，`N` / `B` 上一个/下一个文件，
  `S` 截图，`I` 诊断
  （`T` `P` `I` `N` `B` `Ctrl+C` 需要**高级模式**开着，
  也就是右键菜单最上面那个勾）
  `Shift+←` / `Shift+→` / `Shift+L` 标 A 点 / 标 B 点 / 清除 A-B 循环，
  `Ctrl+←` / `Ctrl+→` 字幕延迟，`Alt+←` / `Alt+→` 音频延迟
  `Ctrl+C` 复制诊断报告、`?` 快捷键总览、`F` 影院模式、`F11` 全屏、
  `Esc` 退出影院模式 / 全屏 / 关面板；
  单击画面切换播放暂停，双击画面切换影院模式
- 支持 MP4、MKV、AVI、MOV、WebM、FLV、WMV 等常见容器
- 支持 H.264、HEVC、VP9、AV1、MPEG-4 等视频编码
- 支持 AAC、MP3、Opus、Vorbis、FLAC 等音频编码
- 界面按显示器 DPI 自动缩放，没有开关也没有「高质量/兼容」之类选项
- 安装时可勾选「创建桌面快捷方式」（默认勾选），卸载时会删掉
- 界面语言在安装时选择（English / 简体中文），选择结果记进注册表，
  程序每次启动按它显示；便携运行可用 `VIDEOVIEW_LANG=en` 或 `zh-CN` 覆盖
- 控件宽度按当前语言的**实测文字宽度**计算，不是写死的常量 ——
  中文两字与英文单词长度差很多，写死必然有一边被截断

## 技术栈

- **界面**：原生 Win32 + GDI 手绘，没有浏览器、没有 WebView、没有前端工程
- **语言**：Rust（`windows` crate 直接调 Win32 API）
- **播放核心**：libmpv（运行时动态加载 `libmpv-2.dll`，构建期零 C 依赖）
- **视频窗口**：Win32 子窗口（`CreateWindowExW`），mpv 直接渲染到 HWND

界面这一层是 v0.2.0 的重写。原来用的是 Tauri + WebView2，
Chromium 进程光内存就占掉 320MB，而且文字受位图缩放影响，
放大后在 125% / 150% 缩放下会发虚。换成 GDI 之后文字按字体 hinting
直接画到目标设备，放大后依然锐利。

空闲与低分辨率播放实测（125% 缩放，H.264，`hwdec-current = d3d11va`，
磁盘上的 exe 原地运行，不含任何打包处理）：

| 状态 | 窗口 | 工作集 | private | GPU 3D | GPU 解码 | 共享显存 |
| --- | --- | --- | --- | --- | --- | --- |
| 空闲 | 1082×673 | 49 MB | 33 MB | ~0 | ~0 | 7 MB |
| 空闲 | 1882×953 | 47 MB | 33 MB | ~0 | ~0 | 13 MB |
| 播放 640×480 | 1082×673 | 135 MB | 115 MB | 4.0% | 0.7% | 46 MB |
| 播放 640×480 | 1882×953 | 142 MB | 122 MB | 7.4% | 0.8% | 64 MB |

连续播放 60 秒工作集无增长（130.4 → 125.7 MB，末值反而更低，说明没有泄漏）。
v0.1.0 是 7 个进程共 442 MB 工作集。

**关于播放时的 135 MB**：其中 **62.7 MB 是三个 Intel 驱动模块**
（`igc64.dll` / `igd11dxva64.dll` / `igd10umdgen11.dll`），是 D3D11 渲染路径的
固定开销，不是解码本身。实测关掉硬件解码内存几乎不变（110.8 → 106.4 MB），
因为 `vo=gpu` + `gpu-context=d3d11` 照样会加载它们 —— 而硬件解码更省 CPU，
所以保留。空闲态 47–49 MB。

**关于 GPU 那一列**：低分辨率时负载几乎全在 3D 引擎（把视频放大铺满窗口），
不在解码。3D 占用随窗口面积上涨，因为每帧要做一次全屏缩放。

### 1080p 与 4K

下面这张表用 `scripts/measure-usage.ps1` 采，**窗口固定 1882×923**
（尺寸必须固定 —— 3D 占用对面积极其敏感），每个文件跑 12 秒取中位数，
整体再跑三轮取中位数。素材由 `scripts/make-test-media.ps1` 生成。
GPU 两列取自 `GPU Engine` 性能计数器，也就是任务管理器「引擎」列的同一个数据源。

机器是 **Intel Celeron N5095**（4 核 2.0 GHz，UHD 600 核显），系统当时有 16% 的
背景负载。**CPU 那一列不要当真**：同一条素材三轮读数能差一倍以上
（1080p 三轮 14.7% / 10.0% / 8.6%），低分辨率下的真实占用本来就低于这台
机器的噪声底。GPU 与内存两列三轮的偏差在 ±2% 以内，下面用的是它们。

| 素材 | 分辨率 | 工作集 | private | CPU（单核） | GPU 3D | GPU 解码 |
| --- | --- | --- | --- | --- | --- | --- |
| `h264.mp4` | 320×240 | 110 MB | 90 MB | 不可靠 | 3.3% | 0.3% |
| `loop60s.mp4` | 640×480 | 131 MB | 110 MB | 不可靠 | 5.3% | 0.7% |
| `h264-1080p.mp4` | 1280×720 | 185 MB | 166 MB | 不可靠 | 11.5% | 2.4% |
| `h264-4k.mp4` | 3840×2160 | 770 MB | 755 MB | 不可靠 | 51.7% | 20.9% |
| `hevc-4k.mp4` | 3840×2160 | 784 MB | 784 MB | 不可靠 | 51.7% | 18.4% |

**4K 的 760 MB 是固定开销，不是泄漏。** 连播 60 秒逐点采样：
746 → 761 → 761 → 761 → 761 → 761 MB，20 秒之后完全持平；播放结束后
掉回 92 MB 空闲态。H.264 一帧 4K 是 12.4 MB，硬件解码的参考帧池加上
D3D11 零拷贝的上传缓冲就是这个量级 —— 它随分辨率走，不随时间走。

**Video Decode 从 320×240 到 4K 涨了约 70 倍**（0.3% → 20.9%），而像素数只涨
144 倍，说明这部分负载基本与像素数成正比。720p → 4K 是 8.7 倍 / 5.2 倍像素，
同样接近线性。之前这张表只有 640×480 一行、还挂着「不代表 1080p/4K」的
免责声明，现在那行没了。

**HEVC 4K 的 CPU 明显高于 H.264 4K**（三轮中位数 26.0% vs 13.7%，且三轮区间
不重叠，是稳定的），但 GPU 解码两列差不多。**原因没有查清** —— UHD 600
理论上是能硬解 HEVC 的，但这里没有做对照实验（没有试过强制软解、也没有确认
`hwdec-current` 在 HEVC 下报的是什么），所以只记录现象。

素材本身都是 `testsrc2` 合成的，**码率远高于同分辨率的真实内容**
（4K 用了 20.7 Mbps）。解码负载取决于分辨率与帧率而不取决于码率，所以这两列
的结论对真实素材同样成立；但**文件大小不能拿这些当参考**。

### 解码诊断

按 `I` 打开。它显示的不是「播放器自己的状态」而是 mpv 报的观测项，并且
给一条**结论**而不是把数字抄给你：

| 显示 | 含义 |
| --- | --- |
| `d3d11va + 零拷贝` | 硬解生效，且解码帧直接进了 GPU、没有 CPU 往返 |
| `软解` | **硬解没生效**，mpv 已静默退回软件解码 |
| `25.0/25.0` | 实际帧率 / 文件标称帧率。明显小于后者说明解码跟不上 |
| `0 / 0` | 解码器丢帧 / 显示端丢帧。启动瞬间丢几帧是正常的，持续上涨不是 |
| `结论` 一行 | 上面几项综合出来的判断 + 具体可查的原因 |

`Ctrl+C` 把同样的内容加上版本、mpv API 版本、物理核数、**显卡名**、
未接入的虚拟显示器数量、DPI 一起复制到剪贴板，可以直接贴进 issue。

**为什么要专门做这个**：D3D11VA 在某个适配器上做格式探测失败时，mpv
**不发任何 error 或 warning**，只是把 `hwdec` 从白名单里拿掉继续用软解。
在低端机上这是最难排查的性能问题 —— 画面能播，但 CPU 跑满、机器发烫，
用户只会觉得「这个播放器慢」。典型触发场景是机器上装了虚拟显示器
（远程控制 / 投屏 / 采集软件会装 IddCx 虚拟适配器），它可能出现在 DXGI
枚举里，一旦被 Windows 选成默认适配器就是这个结果。

本机实测：硬解生效（`d3d11va` + 零拷贝），但 `EnumDisplayDevicesW` 返回
**13 个**显示设备、其中 12 个未接入，绝大多数是远程投屏软件装的
`GameViewer Virtual Display Adapter`。这类机器上「静默降级」的概率明显更高，
所以诊断报告把未接入设备的数量单独列成一行。

### 画面右键菜单

在画面上点右键。高级功能在这一处找齐：

```
✓ 高级模式
────────────
打开文件...
播放 / 暂停
停止
────────────
音轨          ▸
字幕轨        ▸   └─ 里面还有「字幕编码 ▸」与「字幕大小 ▸」
────────────
截图
后退一帧
前进一帧
────────────
减速
重置速度
加速
────────────
跳到开头
后退 10 秒
前进 10 秒
跳到结尾
────────────
影院模式
全屏
解码诊断
快捷键总览
────────────
复制诊断报告
────────────
下一个文件
上一个文件
────────────
时间              ▸   └─ A-B 循环 + 字幕/音频延迟
```

用的是**系统原生菜单**（`TrackPopupMenuEx`），不是自绘 —— 自绘要处理
无障碍、DPI 缩放、屏幕边缘翻转、子菜单悬停延迟、禁用态灰度、高对比度模式
下的配色，这些系统都做好了，而且是用户熟悉的样子。

菜单**是浮层**，不吃画面区：画面高度不变，随时按 `Esc` 关掉都不会留下什么。

两类状态都直接画在菜单上，不用点进去才知道：

- **打勾**：高级模式、影院模式、全屏、解码诊断（开着时）、当前音轨、
  当前字幕轨、当前字幕编码、当前字幕大小，以及字幕轨那一组的「关闭」
  （当前没字幕在放时它是选中态）
- **置灰**：没媒体时的播放/停止/截图/逐帧/跳转/下一个/上一个；没变速时的
  「重置速度」；文件里没有某类轨道时对应的子菜单；**高级模式关着时的
  解码诊断 / 快捷键总览 / 复制诊断报告 / 字幕编码 / 字幕大小**

没有轨道时子菜单**保留但置灰**，里面一行「（这个文件没有音轨）」。不这么做
的话父菜单会少一项，后面每一项都往上挪，而肌肉记忆会停在老位置 —— 第二次
打开菜单就点到别的命令。

**高级模式开关放在最上面**，而且单独一组：它决定下面一堆项能不能用，
放底部的话用户要滚到最后才知道为什么它们是灰的。它**默认是开的** ——
默认关掉等于「装好之后按 `I` / `T` 没反应」，而没有任何界面元素告诉用户
「你得先去菜单里开一个开关」。所以它的实际语义是「简化模式」：
关掉给一个干净的基础界面。

「字幕编码」与「字幕大小」是**字幕轨子菜单里的**两个子菜单，不是主菜单上
的两项。它们只对字幕生效，而主菜单已经 24 项了；放进字幕菜单的好处是
「字幕乱码」和「字幕太大」这两件事会在同一个地方被找到。

**快捷键一个都没删。** 菜单是快捷键的第二个入口而不是替代品：快捷键本来
就存在、成本为零，而菜单是「不知道有快捷键」的用户唯一的发现途径。

### 音轨与字幕轨

按 `T` 打开（右键菜单里也有「音轨 ▸」/「字幕轨 ▸」）。这个面板在控制栏
上方占一块，**不是浮在画面上** —— mpv 的画面是原生子窗口，盖在主窗口的
一切绘制之上，浮层要自己管 Z 序；走现成布局路径（把画面区顶矮）零风险。
代价是面板开着的时候画面矮一点。

面板期间 `↑` `↓` 移动光标、`Enter` 选中、`Esc` 关闭 —— 方向键归菜单，
不再调音量。这是标准菜单行为：不然用户在菜单里按 `↑` 会听到音量变而高亮
纹丝不动，两件事同时发生、其中一件显然不是他要的。

一行上的记号：

| 记号 | 含义 |
| --- | --- |
| `●` | 正在用的那条 |
| `▸` | 文件的默认轨（可以和 `●` 同时出现） |
| `外挂` | 外挂字幕，不是内嵌在容器里的 |

**拖 `.srt` 进窗口就是加外挂字幕**，不替换当前视频 —— 用的是 mpv 的
`sub-add` 而不是 `loadfile`。「打开文件」对话框里选字幕文件也是同一件事
（两条入口一致，不会出现「拖进来能外挂、从对话框选却打不开」）。
认四种扩展名（`.srt` / `.ass` / `.ssa` / `.vtt`，大小写都认）；别的扩展名
当媒体处理，因为判错的后果不对称：把字幕当视频打开会失败并报错，把视频
当字幕加载则是一条不存在的外挂轨。

成功时**不弹框**：字幕立刻出现在画面上，菜单里多一行带 `●` 的条目。
失败才弹窗。拖放一次只取第一个文件 —— 同时拖 `movie.mp4` + `movie.zh.srt`
只会打开视频，字幕被丢掉。

`J` / `L` / `A` 是快捷键，两端都绕回。字幕轨只有一条时按 `J` / `L` 等于
没按 —— 这不是错误，所以不弹提示。字幕被关掉之后 `J` / `L` 会**打开**
字幕（挑文件声明的默认轨），不是变成死键。mpv 自己的 `cycle sub` 不适合
这里：它把「关掉字幕」也算进循环，按一下可能什么都看不见（用户以为坏了），
而且没有「往前」的方向。

字幕编码（`sub-encoding`）与 `sub-scale` **这一版没做** —— 它们要一个子菜单，
和这次的轨道菜单不是一块 UI。

## 设置存在哪儿

所有设置都是**按用户**存的，换用户互不影响，也不需要管理员权限。

| 内容 | 位置 |
| --- | --- |
| 音量、静音、窗口大小、高级模式、倍速、字幕大小、字幕编码 | 注册表 `HKCU\Software\VideoView` |
| 上次播放位置（每个文件一条） | `%LOCALAPPDATA%\VideoView\resume.txt` |
| 界面语言 | 注册表（安装时选定） |

**为什么播放位置不放注册表**：位置是**按文件**记的，一个 40 集的番剧要记
40 条。注册表是「按值名记的」，塞 40 条得自己编一套 `pos_<hash>` 这样的
值名 —— 而那个 hash 要么会碰撞，要么得把路径本身当值名（注册表值名有长度
上限，长路径会被截断，而截断之后两个文件可能撞在一起，于是记得串了）。
一行一个条目更简单，而条目数上限本来就小（几百条也就几十 KB）。

写入是**原子的**：先写同目录的 `resume.txt.tmp`，再 `rename`。直接
`fs::write` 的话中途断电会留下半个文件，而条目在文件里的顺序每次启动都不同
（遍历的是 `HashMap`），所以丢掉的是**随机的一半**，下一次启动读到残缺文件
又原样写回去，丢失就固化了。

`resume.txt` 的格式是 `<路径字节数> <秒数>` 一行、路径原文一行，两行一条。
**带长度前缀是因为 Windows 允许文件名里有换行**，按行切分的话那会把一个
路径切成两半，得到两个都不存在的路径。

## 构建

前置条件：Rust 1.77+、NSIS 3.x（仅打包安装包时需要）。

Windows SDK（提供 `rc.exe`）**可选**：它只用来把图标和版本信息嵌进 exe。
`build.rs` 找不到 `rc.exe` 时只打印一条告警并继续，产物照样能编译能跑，
只是没有图标、`FileVersion` 为 0。调试时不必先装 SDK。

```powershell
# 1. 获取 libmpv（按 scripts/libmpv.lock.json 锁定的版本下载并校验哈希）
powershell -ExecutionPolicy Bypass -File scripts\fetch-libmpv.ps1

# 2. 编译
cd src-tauri
cargo build --release

# 3. 打安装包 + 免安装 zip
cd ..
powershell -ExecutionPolicy Bypass -File scripts\package.ps1
```

`package.ps1` 自己会校验 exe 里嵌的 `FileVersion` 与 `Cargo.toml` 一致，
所以**发布前必须装上 Windows SDK**——否则那个校验会因为版本号为 0 而中止，
打包流程不会静默产出一个「控制面板显示 0.0.0」的包。

产物在 `artifacts/`：

| 文件 | 说明 |
| --- | --- |
| `VideoView-Setup-<版本>.exe` | NSIS 安装程序，压缩后约 33 MB（解压约 116 MB） |
| `VideoView-<版本>.zip` | 免安装压缩包，解压即用 |

两个产物都含 `libmpv-2.dll`，装出来/解压出来共约 116 MB，
压缩后 33 MB（安装包）/ 46 MB（zip）——体积基本全是这个 DLL。

`package.ps1` 在铺暂存目录时会再校验一次 `libmpv-2.dll` 的 SHA-256，
并核对两处版本号与 `Cargo.toml` 是否一致，任一不符就中止：

- exe 里嵌的文件版本号（`FileVersion`，由 `build.rs` 从 `CARGO_PKG_VERSION`
  注入）
- `assets/app.manifest` 的程序集清单版本（`assemblyIdentity/@version`，
  `build.rs` **不**替换它，必须手动同步）

发布出去的包不该出现「文件名写 0.6.0、资源里却是 0.5.0」这种不一致。
两个检查缺一不可：只查 FileVersion 是抓不到清单版本漂移的。


界面是 GDI 自绘的，`cargo test` 覆盖不到「像素真的贴对了地方」。
发布前手动跑一次端到端验收（会抢前台窗口、发送键鼠事件）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\verify-ui.ps1
```

**42 项检查**，全部通过才退出 0。其中有几项专门防「静默失效」——
写盘失败被 `let _ =` 吃掉、错误发生在异步事件那侧、像素判据恰好在出错时
也成立，这些都不会让程序崩溃，只会让某个功能默默不工作，而界面看不出
任何区别：

- `resumeWrittenOnExit`：正常关窗（`WM_CLOSE`）之后 `resume.txt` 存在。
  必须走正常关窗 —— 退出时那次强制写盘在 `WM_CLOSE` 之后才跑，强杀到不了。
- `resumeSeeksBack`：**把同一个文件开两次**比进度条 —— 一次留着记忆文件
  （应当跳到上次位置），一次删掉（必然从头）。只验「位置写下来了」是不够的，
  「下次会跳过去」是另外一半。
- `speedLabelShows` / `abPointShowsNotice` / `subDelayShowsNotice` /
  `subDelayReverseWorks` / `audioDelayShowsNotice`：控制栏那一行字在按
  快捷键之后必须变。这几组带修饰键的键**只能用真键盘事件验** ——
  应用读的是 `GetKeyState`，伪造的 `WM_KEYDOWN` 改不了键盘状态，
  发过去的 `Ctrl+→` 在应用看来就是光秃秃的 `→`。
  `subDelayReverseWorks` 单列一条是因为「按了有反应」验不出方向写反。
- `subMenuOpens`：判据是 **#32768 的 HWND 变了**（弹出菜单每一层都是独立的
  顶层窗口），并且**逐个 ↓ 试**去找有子菜单的那项，不依赖菜单项顺序 ——
  加一项菜单就挂的教训。

## 供应链

播放核心是被 `LoadLibrary` 进本进程并执行的第三方二进制，因此下载环节
不做任何版本选择：

- 版本与两个 SHA-256（压缩包、解压出的 DLL）锁定在
  [`scripts/libmpv.lock.json`](scripts/libmpv.lock.json)
- `fetch-libmpv.ps1` 只下载锁定 tag 下的锁定资产，逐层校验哈希，
  任何一层对不上就中止，不会把未校验的二进制写进构建输入路径
- 本地已有的 `libmpv-2.dll` 每次也会校验；不匹配时脚本拒绝覆盖，
  需要显式 `-Force`
- `package.ps1` 在打包时再校验一次，确保进包的 DLL 就是锁定的那一份

因此「谁构建、什么时候构建」不影响产物里的播放核心是哪一份字节。

## 安全相关行为

- 不读取 `%APPDATA%\mpv` 下的用户配置，也不加载任何 mpv 脚本
  （`config=no`、`load-scripts=no`、`ytdl=no`）
- 只接受磁盘上确实存在的普通文件。mpv 的 `loadfile` 第一个参数是 URL 而不
  只是文件名，校验点放在 `MpvPlayer::load_file` 这一个入口上
- 正式版只在 exe 同级查找 `libmpv-2.dll`，不向上遍历父目录，
  也不探测子目录——否则 `C:\Program Files\` 或用户目录里任意一个同名
  DLL 都可能被优先加载（DLL 劫持）
- 安装程序不改动文件关联。想关联的第一次启动时自己选一次即可
